# Red Engine headless research foundation

This is a small headless research service for the Studio 2.5 feature prototype. It is separate from the captured RedNote mirror and from the Studio UI.

The new study slice has three explicit parts: `study_core.py` owns scope validation and evidence rules, `study_storage.py` owns the SQLite archive/study adapters, and `research_service.py` exposes bounded local HTTP commands. `study_cli.py` provides the same study operations without any browser or Studio process.

- Presets live in data/research-presets.sqlite, with research_presets and preset_terms tables. The default preset is derived from the user-authored RED ENGINE.zip, inside RED ENGINE/messages/01_user.md. Startup inserts it only if absent, so later database edits are preserved.
- The source archive at ../Red Note Gemini/data_v2/rednote-v2.sqlite is opened in SQLite read-only/query-only mode. The service never alters captured profiles, posts, comments, or media.
- GET /api/presets lists stored presets; POST /api/presets saves a new custom preset; GET /api/search returns bounded post/comment text matches ranked by preset term weights. Results include source links, matched terms, and archive scope. Search is lexical only; it does not infer commenter gender, attraction, purchases, or wider population percentages.
- Studio's local presentation server proxies only these routes through /research/. The research service itself serves no HTML.
- Study manifests live in a separate `data/studies.sqlite`. Creating a study selects captured profile IDs and optionally post IDs, then records IDs, source revisions where available, content hashes, counts and coverage. The mirror is read-only. A later source read recomputes its hash and reports `source_changed` or `source_missing` rather than silently substituting updated content. This is a pinned manifest, not a copy of all source text or media.
- `GET /api/coverage` inventories the current captured archive. `GET /api/studies`, `GET /api/studies/{id}`, `GET /api/studies/{id}/records?kind=post&cursor=0&limit=30`, `GET /api/studies/{id}/sources/{kind}/{entity_id}`, and `GET /api/studies/{id}/threads/{post_id}` are headless study queries. `POST /api/studies` creates an immutable study; it requires `X-Red-Engine-Action: explicit` and a JSON body with `title`, `question`, `profile_ids`, optional `post_ids`, and optional `preset_id`.
- `POST /api/studies/{id}/measurements` with `X-Red-Engine-Action: explicit` and an empty body saves a deterministic captured-inventory run. The engine first checks every profile, post, comment and asset against the study's pinned source hash; changed, added or missing records block the run. `GET /api/studies/{id}/measurements` lists immutable receipts and `GET /api/studies/{id}/measurements/{run_id}` reads a result. Runs count only captured records, coverage states, source account IDs, replies and asset-file verification. They make no demographic, sales or attraction inference.
- `GET /api/studies/{id}/search?q=...&kind=all&cursor=0&limit=30` searches exact text within the selected study after verifying all its pins. It returns original-language excerpts, source IDs and hashes, match counts and captured post/comment denominators. This is distinct from the older unscoped preset search.
- `POST /api/studies/{id}/contexts` with `X-Red-Engine-Action: explicit` creates a saved evidence package from an explicit task, 1–5 selected post IDs, up to 50 comment IDs and up to 20 asset IDs. Selected records must be pinned and beneath the selected posts. The package stores original text and media descriptors, capped at 96 KB; it includes no media bytes or credentials and is **not sent to a model**. `GET /api/studies/{id}/contexts` lists packages; `GET /api/studies/{id}/contexts/{context_id}` reads one and checks selected source freshness again.
- `POST /api/studies/{id}/jobs` with `X-Red-Engine-Action: explicit` and `{"provider":"codex"|"gemini","context_id":"context-...","model":""}` records a durable `awaiting_session` request for a fresh evidence package. No model call occurs. `GET /api/studies/{id}/jobs` and `GET /api/studies/{id}/jobs/{job_id}` read the request and append-only state events. `POST /api/studies/{id}/jobs/{job_id}/cancel` with an empty body cancels only an unsent awaiting-session request.
- Studio's presentation host now allowlists these bounded research routes at `/research/api/...` and the broader status route at `/engine/api/engine/system`. It does not own the databases or the study logic.

Start with: python "D:\0\Noir Fiction Engine\Red_Engine\research_service.py"

To bring up both headless services on this machine, run `powershell -File "D:\0\Noir Fiction Engine\Red_Engine\Start-RedNoteEngines.ps1"`. It reuses healthy local services and refuses a port owned by something else. The archive service uses `Reel_Harvest/rednote_engine/server.py` at port 5182 against the existing `Red Note Gemini` archive in read-only mode. `GET /api/engine/system` reports archive counts and separate acquisition, derived-job, assistant and research readiness. Browser capture is unavailable in this read-only configuration; the script does not start a clone job.

The service binds to 127.0.0.1:5188. The Studio page is http://127.0.0.1:5185/red-engine-features.html.

Example independent of Studio: `python "D:\0\Noir Fiction Engine\Red_Engine\study_cli.py" coverage`. To create a study, pass `--title`, `--question`, and at least one `--profile-id` from coverage. Omitting `--post-id` includes every captured post under the selected profiles. Study IDs and source hashes remain in the Red Engine database; no graph geometry is stored.

Run a pinned inventory with `python "D:\0\Noir Fiction Engine\Red_Engine\study_cli.py" measure STUDY_ID`; use `measurements STUDY_ID` and `measurement STUDY_ID RUN_ID` to read saved receipts. Each run is retained rather than overwriting earlier analysis.

The CLI also supports `search STUDY_ID QUERY` and `context-create STUDY_ID --task TEXT --post-id POST_ID` (repeat `--comment-id` and `--asset-id` as needed). Use `contexts STUDY_ID` and `context STUDY_ID CONTEXT_ID` to inspect a saved package. These operations work without Studio, Codex or Gemini sessions.

`derived-reading STUDY_ID post|comment ENTITY_ID` reads current source-checked machine translations, OCR, and transcripts from the mirror as **unreviewed reading aids**. `context-create` accepts `--include-english-aids`; the selected original Chinese remains the citable source, and the package rechecks both source and derivative hashes when read. `media-context` also reports source-linked OCR frames and timestamps. A proposed finding can pin an exact Chinese OCR line using its video asset ID, OCR derivative ID, and frame timestamp; the engine rechecks all three when reading the finding. The same bounded reading is available at `GET /api/studies/{id}/derived-reading/{kind}/{entity_id}`. See `TRANSLATION_CAPTURE_ANALYSIS_PASS_2026-10-11.md` for the live sample and its limits.

`job-create STUDY_ID CONTEXT_ID --provider codex|gemini` records an unsent analysis request; `jobs`, `job`, `job-cancel`, `job-retry` and `job-recover` expose durable state. A cancelled or failed request is resent only after an explicit retry and dispatch. A running cancellation interrupts Codex through its bridge; the Antigravity adapter stops waiting locally, so its remote outcome remains unknown. Restart recovery marks expired running leases interrupted or cancelled and never resends automatically.

`job-dispatch-codex STUDY_ID JOB_ID` checks the signed-in Codex account and model catalog, sends only the saved context with tools disabled, and saves valid output as `proposed_unreviewed`. `job-dispatch-gemini STUDY_ID JOB_ID` uses the installed Antigravity bridge kit, a non-secret project ID in `gemini-project.json`, and the active sidecar session. It sends one bounded context and rejects responses that invoke tools, return invalid JSON, cite an unselected source, or quote text that is not an exact source substring. `job-output STUDY_ID JOB_ID` reads a saved proposal and output hash. Both adapters were used for real runs on 2026-10-11; their outputs are proposals, not approved findings.

`codex-status` probes the signed-in account and live model catalog without sending study content. `gemini-status` checks Antigravity transport, project context and sidecar availability but does not claim model entitlement from hardcoded model labels. A validated completed turn is required to verify inference. The Antigravity Windows command parser truncates a positional prompt at a literal newline, so the adapter sends a single-line argument containing JSON-escaped source text.

`marketing-measure STUDY_ID` saves terminology counts, captured post/comment denominators, discussion structure, and media-file verification. `media-context STUDY_ID POST_ID` returns source-pinned media metadata without scene or audio inference. `finding-create`, `findings`, and `finding` create and inspect source-linked proposals with exact quotes, counterevidence or a documented counter-search, scope, and limitations. `finding-review STUDY_ID FINDING_ID --decision approve|reject|request_changes --reviewer NAME --rationale TEXT` requires a named human reviewer; no provider can mark its own result reviewed. Equivalent headless HTTP routes are in `research_service.py` and require `X-Red-Engine-Action: explicit` for mutations.

The measured slice and real-session receipts are in `ANALYSIS_AND_SESSIONS_2026-10-11.md`. Source pins detect mirror changes; they do not freeze archive bytes. The engine does not infer demographics, sales, image content, or a representative population from lexical matches. Studio has no binding for the new review controls yet; the CLI is immediately usable, while the existing port-5188 process must restart to load newly added HTTP routes.

## Archive reconciliation and index

`archive_foundation.py` is a separate data-foundation command. `python archive_foundation.py audit --output data/archive-audit.json` reads both captured databases, compares every imported JSON revision, checks local media size and SHA-256, and reports coverage/parent gaps. It does not mutate either archive. `python archive_foundation.py decode --output data/media-decode.json` loads each saved image and decodes one frame per saved video. `python archive_foundation.py index` builds an atomic, disposable `data/source-index.sqlite` containing captured post/comment text plus separately marked legacy rows; it does **not** merge legacy-only identities or discussion into the mirror. `python archive_foundation.py search --query 词语` searches exact original text in that index and rejects it if the mirror has changed. `python archive_foundation.py snapshot` makes SQLite-backup copies and hash-checked imported JSON copies; media bytes are represented by a manifest, not duplicated.

The 2026-10-11 audit and capture bottleneck findings are in `CAPTURE_FOUNDATION_AUDIT_2026-10-11.md`. The native RedNote application owns the actual app browser and can host capture when open; the separate read-only service at port 5182 still cannot start or resume capture. Its system status now reports the native host separately, without exposing its bridge token. The packaged native build does not expose a derived-worker health bit yet; an invalid no-op request confirmed that its derived route was attached in this session without queuing a job. An owned future headless server can opt in to import and derived workers with `--enable-derived`, but the read-only preview rejects that flag. No clone or derived job is auto-started by these new data-foundation commands.
