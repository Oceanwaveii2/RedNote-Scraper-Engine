# RedNote login and capture research — 2026-10-11

## Decision

Keep the user's normal RedNote sign-in inside the persistent, app-owned WebView2 session. Browse, capture, and research use separate windows in that session; background work does not activate the foreground window. Never copy cookies, intercept login codes, solve challenges, or silently restart a blocked job. Keep the established 10-second post and 10-second media pacing until measured site behavior supports a change.

The official Open Platform is worth tracking as an optional future account-identity integration. Its current published scope is `basic_info` only; `user_profile`, `read_notes`, and followers access are listed as planned. It cannot replace this app's saved-post, comment, or public-profile research path today. The documented OAuth `open_id` is app-specific and should not be joined to captured profile IDs without a verified mapping. [Official scopes](https://openaccount.xiaohongshu.com/docs/scope) · [Official FAQ](https://openaccount.xiaohongshu.com/docs/faq)

## Current implementation reviewed

- `desktop_bridge.py` creates manual Browse, hidden Capture, and hidden Research WebViews under one persistent `browser-session` folder. On cooldown, Browse starts with a local pause notice. Capture and Research do not restore or focus a user window.
- `rednote_v2/research_browser.py` checks visible login, challenge, and rate-limit states, then returns a gate result. It does not read cookies or bypass a gate.
- `profile_clone.py` preserves checkpoints, 10/10 pacing, attachment budgets, and explicit resume. The current gap is that a user sees the gate mainly through job state and may not immediately know which window or action is needed.
- `browser_capture.py` reads normally rendered comments and visible reply branches. Media in comments can be classified and captured, but old archive entries need paced revisits to reconstruct inline text/media order.
- Comment author IDs link to a live profile. The link is enough for navigation; the app should not clone commenter pages by default. Red Engine can request a one-page observation and must label any location or identity field as self-described, unverified source content.

## Recommended improvements, in order

1. **Login and gate state machine.** Separate `signed_in`, `login_required`, `challenge`, `rate_limited`, `network_error`, `page_changed`, and `unknown` based on rendered page evidence and navigation result. Persist only the state, evidence timestamp, current URL class, and job checkpoint, never credentials. A paused job should say `Open Browse to sign in` or `Resolve RedNote challenge`, with one explicit resume action. WebView2 navigation exposes success, HTTP status, and web error fields, but a successful navigation alone does not prove a signed-in page. [Microsoft navigation result](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/winrt/microsoft_web_webview2_core/corewebview2navigationcompletedeventargs?view=webview2-winrt-1.0.3856.49)
2. **Session ownership and recovery.** Keep one app process as owner of the existing user data folder, prevent simultaneous archive writers, show a session-health indicator, and never clear the folder automatically. When moving the folder, close all WebViews and wait for browser processes to exit. Microsoft documents that a UDF stores cookies and cached resources, can be shared by WebViews in one session, and should persist when sign-in must persist. [Microsoft user data folders](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/user-data-folder)
3. **Background research scheduling.** One bounded site-action queue should arbitrate Capture and Research requests against the same signed-in account. Preserve the 10/10 minimum pacing, per-job checkpoints, cooldown, and cancellation. A retry after challenge must be user-triggered. Expose counts of requests, reused media, page waits, failed branches, and source coverage without displaying cookies or signed URLs.
4. **Commenter traversal.** Keep avatar/name as a live link. Red Engine's comment-to-profile operation first checks that the comment is pinned in the study; optional live observation uses the hidden Research window and writes an immutable receipt. Store observations separately from mirror clone data. Do not infer gender, age, or other demographics from a name, avatar, or clothing; distinguish explicit self-description from the analyst's inference.
5. **Content coverage.** Record site-reported count, exposed comment count, expanded reply branches, hidden branch count, attachment saved/missing status, and reason for a gap. Render Unicode emoji directly and classify observed GIF/sticker/gift media explicitly. A missing attachment should link to the source post and remain `partial`, not be marked complete.
6. **Only if approved and useful later: official OAuth.** The published flow supports authorization code, PKCE, refresh, token status, and device/QR authorization, but presently only basic account information. If integrated, keep credentials in an appropriate protected store and separate its consented `open_id` identity from captured public page IDs. Do not extract OAuth tokens from WebView navigation or cookies; Microsoft identifies that as an embedded-browser anti-pattern. [Official quick start](https://openaccount.xiaohongshu.com/docs/quick-start) · [Official API reference](https://openaccount.xiaohongshu.com/docs/api-reference) · [Microsoft WebView2 OAuth guidance](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/webview2)

## Evidence limits

The official docs describe available APIs, not the stability of RedNote's consumer web DOM or permission for unrestricted automated capture. Selector and page-state changes should be checked against the live rendered page before shipping. The existing WebView session has worked for the current account, but a repeatable post-restart login check and a visible user recovery flow are still needed. No claim is made that the official OAuth product grants Saved/Favorites or comment access.

The [official FAQ](https://openaccount.xiaohongshu.com/docs/faq) confirms limits for Open Platform APIs by endpoint and app ID; those limits do not define safe pacing for consumer-site browsing. Its `open_id` is app-specific and authorization can be revoked. Treat this as another reason to keep official OAuth identity separate from source-page identities. Chinese UI strings and site states should be retained alongside any English explanation in gate diagnostics so selector changes can be diagnosed without guessing from translations.

## Implementation status on this date

- The active native build is `2.0.0-candidate-r14`. It shares the existing archive and browser session. Diagnostics showed the archive available and no V2 or master import error after restart. The selected-note capture job remained paused at its checkpoint.
- One bounded revisit preserved 10,717 archived comments and populated 11 ordered rich-comment records for the selected note; five contained inline assets. That note exposed emoji, so GIF, sticker, and gift recognition is implemented but still awaits a real observed example.
- The live archive renders ordered comment media and sends avatar/name clicks to the manual RedNote Browse window. New standalone offline exports also render the ordered media and provide a canonical external source-profile link when a valid commenter ID exists; existing exported HTML must be regenerated to gain this change.
- Red Engine study broker operations resolve a pinned comment to its ordered media and live profile URL. One real optional background profile observation succeeded without cloning the commenter; the receipt labels site-displayed fields as unverified. Gemini provider tool use remains unverified and should not be represented as operational.
- The login and gate state machine, single site-action scheduler, visible recovery prompts, and post-restart sign-in check above remain design work. Preserve existing pacing while implementing them.
