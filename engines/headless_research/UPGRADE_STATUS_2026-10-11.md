# Red Engine and Scatter headless upgrade

This change keeps three boundaries: the captured mirror remains read-only, Red Engine stores study pins and derived research records, and Scatter stores authored graph revisions without importing the prototype board.

## Implemented in source

- A study now records its member projection and a cheap SQLite archive generation signal at creation. The first measurement uses that derived projection; identical later measurements reuse their saved run through a manifest and input keyed cache. A changed archive generation triggers a full source-pin verification once before the projection is refreshed. Existing studies backfill on first use. This does not claim that an unchanged filesystem signal is cryptographic proof; individual cited sources are checked against their pins.
- Study search joins the existing `source-index.sqlite` FTS text records to immutable `study_members`. It validates the index fingerprint once per index/archive generation and refuses stale indexes. Short queries join indexed study membership while scanning the derived text records because trigram FTS cannot narrow one- or two-character terms.
- Background Saved/Favorites/likes and search lists use `research-checkpoints/discovered-lists.sqlite`. Rows are inserted once with unique list/kind/item IDs and ordinal cursors. A legacy list JSON file is imported on first access and retained. Post-comment checkpoints remain in their existing format.
- `research_broker.py` exposes a study-scoped allowlist for captured source/search/thread reads and the app-owned RedNote research window. Tool calls receive append-only local receipts. `broker_dispatch.py` gives Codex dynamic tools and offers Gemini a host-mediated JSON request loop. A final proposal must cite exact captured quotes; live observations remain leads until captured and pinned. This is separate from the older fixed-context analysis jobs.
- `Scatter_Engine/graph.py` adds an authored, headless typed graph store. Commands use expected revisions and idempotency keys. Revisions and command hashes are immutable. Connections must terminate on compatible typed ports, and restore creates a new revision. No prototype board data has been bound or migrated.

## Headless commands

From `Red_Engine`: `python study_cli.py research-dispatch STUDY_ID "question" --provider codex` or `--provider gemini`, and `python study_cli.py research-session SESSION_ID`.

From `Scatter_Engine`: `python graph_cli.py create "Title"`, `python graph_cli.py show PROJECT_ID`, and `python graph_cli.py apply PROJECT_ID EXPECTED_REVISION COMMAND_ID command.json`.

The pre-change files and a SQLite backup of `studies.sqlite` are preserved in `00_ADMIN/Backups/RedScatterUpgrade20261011` with source hashes in `change-manifest.json`.
